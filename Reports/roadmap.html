Roadmap · Phases 5–7 · 27 tickets

From a corpus you can read to a corpus you can design with

Phases 1–4 made datasheet extraction trustworthy. These three phases make it reachable by an agent, shaped like a schematic instead of a table of contents, and honest at twenty parts instead of six.

Where we are

The hard problem is solved. Six parts across four vendors build fully offline, every value is verbatim, every answer carries a printed page number, and a hand-verified golden set gates the whole thing. Nothing below asks you to revisit that foundation.

What is missing is not fidelity. It is that the corpus only answers a caller who already speaks the datasheet's vocabulary, from a shell, about one part at a time. Three gaps, three phases.

Phase 5

Agent-Native Access

dsa query --symbol TJ works. "What is the max junction temperature?" returns nothing. There is no full-text path, so an agent greps section files and attributes pages itself — defeating the provenance guarantee the corpus exists for. A --section 4.9 read costs 9,607 tokens with no warning. And there is no noun above part, though the goal is compiling datasheets for a project.

This phase adds no new extraction. It is surface over data that already exists — which is why it comes first.

A designer's question, in a designer's words, returns a cited answer inside a budget.

The one structural change

Today query.py re-scans and re-parses every specs.json on every call — fine for one CLI invocation, wrong for an MCP session making dozens. A new retrieve/ module becomes the single implementation of every lookup, and both the CLI and the MCP server become thin adapters over it. After this phase, no retrieval logic lives in a front end. That seam is what keeps the two surfaces from ever drifting apart.

Tickets, in dependency order

  1. 01Retrieval core seam

    Cached CorpusIndex + typed results carrying citation, confidence, and which match rung fired. Everything else is an adapter over it.

  2. 02Alias lexicon

    A YAML file mapping designers' words to datasheets' symbols, resolved by a five-rung ladder. Cheapest hit-rate win in the roadmap; adding a synonym is a data change.

    after 01
  3. 03Full-text search

    A precomputed BM25 index built at publish. Every hit carries its section's page range, so search results are cited by construction — no caller ever attributes a page.

    after 01
  4. 04Per-record confidence

    A high/medium/low grade per record from page pinning, the reconstruction gate, and cell completeness. This is what lets an agent say "open p.47" instead of asserting a shaky number.

    after 02
  5. 05Answer packs — dsa ask

    One call, one cited payload, a hard budget with a reserved tail so citations can never be the truncated part. Routing is deterministic — no model inside ask.

    after 02 · 03 · 04
  6. 06Projects

    An explicit part list plus one always-loadable PROJECT_INDEX.md for a whole design. Project-scoped questions label every answer with the part it came from.

    after 01parallel to 02–05
  7. 07MCP server (local stdio)

    Nine tools including get_figure, which returns the PNG as an image block — narrow 514 figures with a filter, receive the one that matters, show it to the designer.

    after 05 · 06
  8. 08Agent protocol files

    AGENT.md shipped inside every corpus, plus an in-repo skill, so the retrieval discipline travels with the data instead of living in a prompt.

    after 07
  9. 09Golden extension + gate

    Natural-language and search-path questions added per part, which must land on the same verbatim answer and page as their symbol-path twins.

    after 07 · 08

Acceptance gate

  • All existing goldens for six parts still at 100%.
  • Every golden question asked in plain language resolves to the same verbatim answer and page as its symbol-path twin.
  • Every search-path question's top-1 hit is the section holding the verified answer.
  • Pack size at or under budget for every golden question — asserted numerically, not spot-checked.
  • Citations survive a deliberately tiny budget; truncation always announces itself.
  • Every MCP tool exercised in-process over the memory transport — no subprocess, no port.
Phase 6

Design-Time Content

After Phase 5 the corpus answers datasheet questions well — but it is still organised the way a datasheet is organised, and it is missing the two tables a designer and a firmware engineer actually live inside. The pin table, which is the datasheet during schematic capture, exists in no queryable form. Register maps route to the degraded paragraphs-only backend, so bring-up questions are unanswerable by construction.

This is where the tool stops helping someone read a datasheet and starts helping someone design with it.

The corpus answers schematic-capture and bring-up questions, and every derived number traces to a printed page.

The contract that makes this safe

These are the first artifacts that are not verbatim-extracted, which puts pressure on the invariant that keeps this repo trustworthy. ADR 0005 resolves it: a derived artifact may contain only verbatim values, values computed from them by a documented pure function, or labels from a checked-in lexicon. Every field carries its source record, its page, and the named rule that produced it. No model call appears anywhere in the derivation path. A field that cannot be filled stays null and says so.

The test that enforces it walks every value on every card and resolves it back to a real record and a printed page. That test is the most important thing in this phase.

Tickets, in dependency order

  1. 01Derived-artifact contract

    ADR 0005, invariant 8, the provenance envelope, and stable record ids that a source field can point at. Contract first — everything conforms to it.

  2. 02Numeric layer

    Parse ranges, bounds, tolerances, and SI prefixes into a parallel field set — and return nothing for See Figure 7. Verbatim stays authoritative; failing is a first-class outcome.

    after 01
  3. 03Device-table abstraction

    Pin tables and register tables are the same animal — wide, repetitive, keyed by a first column. One identify → map → validate → emit pipeline, two consumers.

    after 01
  4. 04Pins

    The most-needed missing artifact. Multi-pin rows expand, types come from a lexicon with unknown as a legitimate answer, and the extracted count is cross-checked against the package's stated count.

    after 03
  5. 05Register summary tables

    Re-routes register maps from the paragraphs-only backend to the layout engine so tables exist at all. Address, name, reset, access — queryable by parsed value.

    after 04blocked · reference PDF
  6. 06Register bit fields

    The hard shape. Explicitly permitted to fail closed: if it cannot pass a 100% accuracy gate, it parks with a recorded shortcoming and ships nothing.

    after 05blocked · reference PDF
  7. 07Design cards

    Power, thermal, interface, and limits — the datasheet reorganised around what you need open while drawing. A card with no data is honestly empty, never invented.

    after 02 · 04
  8. 08Plot axis catalog

    Axis labels, units, and ranges read geometrically, so 514 figures narrow to one before a vision token is spent. Uncertain stays null.

    independent — pick up while blocked
  9. 09Cross-part compare

    Part selection in one call: both verbatim values, both page cites, a delta only where both sides parsed, and an explicit list of what could not be compared.

    after 02 · 07
  10. 10MCP surface + gate

    New artifacts exposed through the Phase 5 seam; ask learns to route pin and register questions; goldens extended; report written.

    after 04 · 07 · 08 · 09

Acceptance gate

  • Pin tables extract for all six parts or are honestly rejected with a recorded reason — no partial pins.json.
  • Every value on every card resolves to a real record and a printed page, checked programmatically.
  • A part lacking a card's data emits an empty card with a stated reason, never a fabricated one.
  • The limits card flags zero-margin parameters — a hazard invisible when abs-max and recommended-operating are read pages apart.
  • Every unparseable-input case returns nothing, asserted individually.
  • Axis metadata on ≥60% of AFE7950's figures at high confidence; the rest honestly null.

Known blocker

Tickets 05 and 06 are needs-info until the reference register-map PDF lands in the repo. A register parser written without a real document to gate against would be fiction.

Ticket 08 is independent of everything else in the phase and is the right work to pick up in the meantime.

Phase 7

Reach & Trust

Three things break as the part count grows from six to sixty. Onboarding is manual, so the BOM-to-corpora path stops at step one. Nothing knows whether a datasheet is current — revisions are parsed and then never questioned. And quality is invisible to the consumer: extraction stats tell the builder how a build went, while nothing tells the agent whether to trust a corpus before answering.

Twenty parts onboard cheaply, stay honest, and a series answers as one.

Tickets, in dependency order

  1. 01Document registry + dsa fetch

    A checked-in URL registry that grows by use, with sha256 verification. A mismatch warns loudly and stops; a miss names the flag that fixes it. No scraping, no search API, no guessing.

  2. 02Revision awareness

    An opt-in network check — never part of build — surfacing staleness in four places, including a footer on every answer. The phase's safety feature.

    after 01
  3. 03Revision diff

    What changed between two revisions: specs, sections, pins, and register reset values. Turns a datasheet update from a re-read into a review.

    after 02 · P6-02
  4. 04Errata cross-linking

    Errata linked to the section or spec they invalidate, with a warning that reaches the answer pack. An item the matcher can't place is still published, never dropped.

    independent
  5. 05Audit scorecard

    Builder statistics promoted into a consumer-readable A–F grade against a checked-in rubric, so an agent can downgrade its own language on a weak corpus.

    after 02
  6. 06Golden generation assist

    Stratified candidates templated from records that already carry verbatim answers and pages. Unconfirmed candidates never count toward verify — the invariant survives intact.

    independent · critical path
  7. 07Part families

    Shared sections listed once, differences tabulated. The direct answer to "become an expert on a series" — and a large token win.

    independent
  8. 08Scale gate + report

    ≥20 parts across ≥3 vendors, an ≥8-part project, a family, every part graded ≥ B or carrying a recorded reason why not.

    after 01–07

The one that matters most

Ticket 02. Right now the tool would answer from a superseded datasheet with full confidence and a valid page cite — an agent that does that without saying so is the most dangerous behaviour this system can have. If the phase gets cut short, keep the staleness warning.

Decisions taken up front

Each of these closed off work a reasonable plan might otherwise have included. Recorded so the reasoning survives the decision.

QuestionChosenRejected, and why
Derived data Deterministic only LLM-assisted-verified (non-deterministic builds, needs a verification harness); LLM free-form (breaks the traceability guarantee)
Project input Explicit part list BOM CSV and EDA netlist parsing — an agent that reads a BOM can call project add, which is the cheap 90%
Document fetch Curated URL registry URL pattern probing (brittle); web-search resolution (non-deterministic, risks a mirrored or wrong document)
MCP Local stdio only HTTP/remote — no team-sharing requirement yet, and auth plus multi-tenancy is real cost
Pins Printed tables only Ball-map reconstruction (vendor-variable); vision fallback (puts a model in the content path)
Registers First-class, gated Indefinite deferral — bring-up matters; but bit fields may still park rather than ship approximate
Plots Axis catalog + hand over the PNG Curve digitization now — a confidently wrong interpolated value is the worst failure this tool could produce
Priority Depth, then breadth Breadth first — would scale a corpus shape still being changed

Critical path
